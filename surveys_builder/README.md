# Конструктор опросов

Приложение существующего Django-проекта. Доступны серверные страницы и JSON API
([контракт](API.md)). Новые зависимости не требуются.

## Запуск

```sh
python manage.py migrate
python manage.py runserver
```

- Все опросы: `/staff/surveys/`.
- Создание: `/staff/surveys_builder/`.
- Библиотека черновиков блоков: `/staff/surveys_builder/block-templates/`.
- Назначенные ученику опросы: `/surveys/`.
- API сотрудника: `/staff/surveys_builder/api/`.
- API ученика: `/surveys/api/`.

### Тестовые ученики

`python manage.py seed_demo_students` добавляет 16 учеников с логинами
`demo_student_01`–`demo_student_16`: классы 10/11, все восемь учебных профилей,
разные статусы, этапы отбора, экзамены и курсы трёх тестовых школ. Регистрация
завершена, аккаунты активны — их можно выбирать получателями и проверять фильтры блоков.
Фамилии в списке отмечены «(тест)». Случайный общий пароль новых аккаунтов выводится
после создания; можно задать свой через `--password`. Повторный запуск не меняет
существующие аккаунты и их данные. Опросы и уведомления команда не отправляет.

## Порядок создания

1. Задать название и описание опроса.
2. Создать блоки или добавить их из библиотеки черновиков. У каждого блока отдельная
   страница содержимого. Внутри добавляются вопросы и текстовые секции с картинками.
3. Выбрать получателей и, при необходимости, срок сдачи. Пустой срок означает,
   что приём ответов не ограничен по времени.
4. Открыть предпросмотр только для чтения и опубликовать опрос.

После названия сразу открывается создание первого блока. В редакторе блока есть постоянная панель
«Все блоки опроса», «Добавить следующий блок» и переход дальше. Если следующий блок уже есть,
основная кнопка ведёт к нему; после последнего — к получателям и сроку. Пустые блоки отмечаются
до перехода к назначению. Настройки, перестановка и удаление свернуты в дополнительные действия.

Содержание готовится до выбора получателей. Вопрос не может существовать без блока.
Доступны короткий и развёрнутый текст, один или несколько вариантов ответа, число,
дата и шкала 1–5. Варианты вводятся отдельными строками с кнопками добавления/удаления;
без JavaScript доступно исходное поле «один вариант в строке».

Блоки, вопросы и секции можно переставлять. Вопрос можно перенести в другой блок
через его редактор. Удаление блока удаляет его вопросы и секции — требуется подтверждение.
Блок может содержать только текст и картинки, без вопросов. Полностью пустой блок
перед публикацией надо заполнить или удалить.

Лимиты: 50 блоков, 100 вопросов на опрос, 100 текстовых секций на блок;
2–50 разных вариантов до 200 символов. Изображения: PNG, JPEG, GIF или WebP,
до 5 МБ и 6000 пикселей по каждой стороне. Текст отображается с экранированием HTML.
Картинки хранятся вне публичного MEDIA_ROOT; выдача проверяет сотрудника или назначение и видимость блока.
Путь можно настроить через SURVEY_PRIVATE_MEDIA_ROOT (по умолчанию соседний с media каталог .media-survey-private).

## Получатели

Назначать можно **только активным ученикам с завершённой регистрацией**
(`is_active=True`, `RegistrationPersonalData.current_step=finish`). Сотрудники
и суперпользователи исключены. Это правило нельзя отключить ни вручную, ни через API.

Выбирается ровно один режим:

- По фильтрам: классы 10/11, учебные профили, статус участия, этап отбора,
  предметы курсов, планируемые экзамены, организации/школы курсов, курсы.
- Конкретным участникам: отмеченные участники из той же допустимой аудитории.

Фильтры добавляются по одному кнопкой «Добавить фильтр» и показываются только после
добавления. Можно убрать отдельный фильтр или сбросить все. Между фильтрами — И,
внутри одного фильтра — ИЛИ. Пустые фильтры не ограничивают аудиторию.
Школа, предмет и курс должны совпасть у одной записи выбранного курса.

Фильтры статуса анкеты, активности аккаунта, завершения регистрации, региона,
поиска по ФИО/email/логину удалены. Нельзя добавлять конкретных участников поверх
выборки по фильтрам. Класс берётся из поля проекта для 2026–2027 учебного года.

## Видимость блоков

У блока доступны все фильтры назначения: классы 10/11, учебные профили, статус участия,
этапы отбора, предметы изучаемых курсов, планируемые экзамены, организации/школы курсов
и курсы. Они настраиваются независимо от получателей опроса. Без них блок виден всем
получателям опроса. Эти условия не добавляют новых получателей — они определяют,
какие блоки видны уже назначенному участнику.

При публикации фиксируются назначения, снимки получателей и список видимых каждому
блоков. Если состав получателей или видимость изменились после предпросмотра,
понадобится новый предпросмотр. Последующее изменение профиля ученика не меняет
зафиксированную видимость. Если кому-то не виден ни один блок, публикация блокируется
с объяснением: нужно исправить фильтры блоков или назначения.

Скрытые блоки, их тексты, изображения и вопросы не выдаются через ученические страницы
и API. Скрытые обязательные вопросы не требуют ответа; подставленный ответ на скрытый
вопрос отклоняется. Текстовый опрос без вопросов можно отправить как подтверждение ознакомления.

## Библиотека черновиков блоков

Черновик можно создать независимо от опроса, наполнить вопросами, текстом и картинками,
а затем использовать в любых опросах. Также можно сохранить существующий блок в библиотеку.
При создании блока доступна кнопка «Создать и добавить в шаблоны», а на странице
содержимого — «Добавить блок в шаблоны». Копия сохраняет текущее содержимое и фильтры;
после сохранения пользователь остаётся в исходном опросе.
При вставке создаётся независимая копия вопросов, вариантов, секций и фильтров видимости.
Изменение или удаление исходного черновика не меняет вставленные копии.

Библиотека использует отдельные черновые записи `SurveysBuilder.is_block_template`.
Они не появляются среди обычных опросов, не назначаются и не публикуются самостоятельно.
Изображения копий ссылаются на сохранённые файлы; удаление записи не удаляет используемые файлы.
Автоматическая очистка файлов, не используемых ни одной записью, не реализована.

## Доступ, результаты и удаление

Все активные сотрудники могут управлять всеми опросами и черновиками блоков.
Ученик видит только свои назначения. Опросы именные, черновики ответов приватны.
После отправки ответ неизменяем. После срока, закрытия или архивирования приём блокируется.
Email и Telegram автоматически не рассылаются.

Доступны счётчики ответов, просмотр отправленных ответов и CSV. В CSV колонки подписаны
`[Блок] Вопрос`; варианты представлены подписями, строки защищены от формул Excel.
На странице всех опросов есть удаление любого опроса с подтверждением. Удаляются
все вопросы, секции, назначения и ответы; аккаунты остаются. API DELETE опроса
по-прежнему разрешён только для черновиков.

Изменения защищены сессией, CSRF, транзакциями, блокировкой опроса и версией `revision`.
Предпросмотр не принимает ответы и не сохраняет их. Публикация требует подписанного
токена с временем действия один час. Повторная публикация не дублирует назначения.

## Миграция и проверки

`0006_block_content_and_assignment` переносит старые вопросы без блока в «Основной блок»,
сохраняет ID, порядок и ответы. Старые назначения получают доступ ко всем прежним блокам.
У черновиков получатели требуют повторного выбора по новым правилам; опубликованные
назначения сохраняются. Применение к рабочей базе требует обычной резервной копии.

```sh
python manage.py test surveys_builder --settings=Putevka.survey_test_settings
python manage.py check --settings=Putevka.survey_test_settings
python manage.py makemigrations --check --dry-run --settings=Putevka.survey_test_settings
```

Тесты используют SQLite в памяти и локальную почту. Конкурентные блокировки PostgreSQL
этим набором не проверяются.

Демонстрационные черновики:

```sh
python manage.py seed_demo_survey
python manage.py seed_demo_survey --with-blocks
python manage.py seed_demo_survey --with-images
```

Команды не отправляют опросы и не перезаписывают уже созданные примеры.
Вариант `--with-images` создаёт отдельный черновик с четырьмя блоками, всеми семью
типами вопросов, пятью текстовыми/графическими секциями и двумя иллюстрациями.
Последний блок не содержит вопросов. Изображения копируются из `demo_assets/`
в закрытое хранилище и доступны через обычный защищённый маршрут секций.
