# Конструктор опросников

Это приложение существующего проекта Django. Бэкенд доступен через JSON API:
управление опросами, выбор получателей, публикация, прохождение и результаты.
Контракт и примеры запросов описаны в [API.md](API.md).
API использует общие сервисы с существующими серверными страницами;
отдельный проект и дополнительные зависимости не нужны.

## Запуск

Из корня проекта, где находится `manage.py`, с активированным окружением:

```sh
python manage.py migrate
python manage.py runserver
```

- Все опросы для сотрудников: `/staff/surveys/` (пункт «Опросы» в меню персонала).
  Включает черновики, опубликованные, закрытые и архивные опросы всех авторов;
  доступны поиск по названию/описанию, фильтр статуса, число получателей и отправленных ответов.
- Создание опроса: `/staff/surveys_builder/` (кнопка «Создать опрос» в общем списке).
- Ученик: `/surveys/` (ссылка «Опросы» в меню личного кабинета).
- API сотрудника: `/staff/surveys_builder/api/`.
- API ученика: `/surveys/api/`.
- Требуется обычный вход в аккаунт проекта. Создавать новые аккаунты для опросов не нужно.

## Порядок работы

1. Создать черновик: название, описание, необязательный срок ответа.
2. Сохранить получателей. Выбрать фильтры или конкретных учеников, проверить выборку.
3. Добавить вопросы. Доступны короткий/длинный текст, один/несколько вариантов, число, дата, шкала 1–5.
   Для вариантов — 2–50 разных строк, до 200 символов каждая. До 100 вопросов на опрос.
   Можно менять порядок, копировать, редактировать и удалять вопросы.
   В разделе «2. Вопросы» можно создавать блоки с названием и описанием (до 50 на опрос),
   выбирать блок при добавлении вопроса и переносить вопрос через редактирование.
   Блоки переставляются кнопками «Блок выше / ниже», вопросы — внутри своего блока.
   При удалении блока вопросы сохраняются в разделе «Без блока», который идёт первым.
   Пустой блок надо заполнить или удалить перед публикацией.
4. Проверить форму и полный список получателей. Проверка заполнения не сохраняет ответов.
5. Опубликовать. Опрос появляется у назначенных учеников. Содержание и получатели фиксируются.
6. Ученик сохраняет черновик и отправляет окончательный ответ. После отправки он неизменяемый.
7. Сотрудник смотрит отправленные ответы и выгружает CSV. Можно закрыть приём или архивировать опрос.

Редактировать можно только черновики. На странице всех опросов доступно удаление любого опроса:
сначала открывается подтверждение с числом назначений и ответов. Подтверждённый POST удаляет
опрос, вопросы, назначения и ответы целиком. API DELETE по-прежнему удаляет только черновики.
Для повторного запуска опубликованного опроса
создаётся копия: вопросы и условия аудитории копируются, ответы, назначения и срок — нет.
Блоки, их порядок и принадлежность вопросов также копируются.
Существующие опросы из миграции 0003 сохраняются как черновики, с прежними вопросами и вариантами.
Для них сначала надо выбрать получателей.

## Связь с моделями проекта

- Аккаунты: `AUTH_USER_MODEL`; сотрудники и суперпользователи не входят в аудиторию.
- `scholar_form.UserInfo`: класс (поле проекта относится к 2026–2027 учебному году),
  учебный профиль, статус участия, этап отбора, статус анкеты, регион, планируемые экзамены.
- `my_study.CourseSelection`, `Course`, `School`, `Subject`: выбранные курсы, организации и предметы.
- `core.RegistrationPersonalData`: завершение регистрации (`current_step=finish`).
- Активность аккаунта — именно `User.is_active`. Статус участия/выпускника выбирается отдельно.

Между группами фильтров — И, внутри группы — ИЛИ. Пустые поля не ограничивают выборку.
На странице получателей значения отмечаются флажками: каждое можно снять отдельно.
Кнопки «Снять выбор» очищают одно поле, «Сбросить все фильтры и списки» — все условия,
включения, исключения и ограничение активности. Обе операции показывают новую выборку,
но не меняют сохранённых получателей до нажатия «Сохранить и перейти к вопросам».
Школа, предмет и курс должны совпасть у одного выбранного курса ученика.
В режиме фильтров конкретные ученики добавляются поверх фильтров (включая фильтр активности);
в индивидуальном режиме остальные фильтры игнорируются, в том числе устаревшие значения справочников.
Исключения имеют приоритет всегда.
Поиск проверяет каждое слово по ФИО, логину и email аккаунта/анкеты;
слова ФИО можно вводить в любом порядке. Регион сравнивается целиком.

До публикации фильтры используют актуальную базу. При публикации создаются `SurveyAssignment`
и снимок имени/логина/класса/профиля/статуса. Последующие изменения профиля не меняют назначения.
Если состав получателей изменился после предпросмотра, нужна повторная проверка.
Неактивный аккаунт может быть назначен явно, но отвечать сможет только после включения аккаунта.
Публикация добавляет опрос в кабинет; рассылка email/Telegram не выполняется.

## Файлы и правила

- `models.py` — опрос, вопрос, варианты, назначение, ответ и значения ответов.
- `QuestionBlock` — блок вопросов; миграция `0005_question_blocks` добавляет блоки без изменения
  существующих вопросов и ответов. У прежних вопросов `block=None`, их порядок сохраняется.
- `selectors.py` — выборка получателей из моделей проекта.
- `forms.py` — Django-формы настройки и динамическая форма прохождения.
- `services.py` — изменения данных, проверка прав/этапов, транзакции, публикация.
- `api.py`, `api_serializers.py` — JSON API и явные форматы ответов.
- `api_urls.py`, `student_api_urls.py` — маршруты API сотрудников и учеников.
- `views.py` / `student_views.py` — страницы сотрудников и учеников.
- `urls.py` / `student_urls.py` — маршруты двух разделов.
- `tests.py` — проверки полного сценария, доступа, валидации, миграции и экспорта.
- `test_api.py` — API: полный сценарий, CSRF, права, ошибки, версии и приватность ответов.

Все активные сотрудники (`is_staff`) могут управлять всеми опросами — как в прежнем конструкторе.
Автор хранится для учёта, но не ограничивает доступ других сотрудников.
Ученик видит только свои назначения. Опросы именные. Сотрудникам видны только окончательно
отправленные ответы; содержимое черновика ученика не выводится в результатах и CSV.
Доступ к базе данных администратора по-прежнему определяется инфраструктурой проекта.

Все изменения выполняются через POST с CSRF. Сервисы повторно проверяют права и состояние,
используют транзакции и блокировку опроса. Версии `revision` защищают от перезаписи из старой вкладки.
Публикация требует подписанного подтверждения из предпросмотра (срок действия — час).
Повтор публикации уже опубликованного опроса не дублирует назначения.
После истечения срока приём блокируется сразу при отправке; отдельная фоновая задача не нужна.
CSV содержит только отправленные ответы, метки вариантов вместо ID и защиту строк от формул Excel.
Удаление аккаунта удаляет его назначения и ответы согласно политике `CASCADE` проекта;
снимок получателей фиксирует изменения профиля, но не служит архивом удалённых аккаунтов.

## Проверки без рабочей базы

Готовый тестовый опрос со всеми семью типами вопросов можно добавить командой:

```sh
python manage.py seed_demo_survey
```

Отдельный пример со всеми типами вопросов, распределёнными по трём блокам
«О вас», «Учёба и интересы», «Планы и оценка»:

```sh
python manage.py seed_demo_survey --with-blocks
```

Он создаётся черновиком с вопросами, подсказками и вариантами ответа; получатели не назначаются,
рассылка и публикация не выполняются. Команда выводит ссылку на предпросмотр для пробного заполнения.
Повторный запуск сохраняет существующий пример и внесённые в него изменения.
Необязательный `--author-id ID` задаёт автора из активных сотрудников.

Проверки:

```sh
python manage.py test surveys_builder --settings=Putevka.survey_test_settings
python manage.py check --settings=Putevka.survey_test_settings
python manage.py makemigrations --check --dry-run --settings=Putevka.survey_test_settings
```

Тестовые настройки используют SQLite в памяти, локальную почту и отключают внешние лог-обработчики.
Они предназначены только для тестов; запускать рабочий сервер с ними не нужно.
Параллельные транзакции PostgreSQL отдельно не проверяются этими SQLite-тестами.
Блоки видны в конструкторе, предпросмотре, форме ученика и просмотре отправленных ответов.
CSV сохраняет общий порядок вопросов; у вопросов из блока заголовок имеет вид `[Блок] Вопрос`.
