# API конструктора опросов

API работает в существующем Django-проекте, без дополнительных пакетов.
После обновления нужно применить миграции: `python manage.py migrate`.
Миграция `surveys_builder/0006` защищает ответ от удаления вместе с назначением.
Приложение `surveys` осталось только для истории миграций: его миграция `0003`
удаляет старые таблицы, если они пусты, и останавливается при наличии записей.
Рабочая база при разработке API не изменялась.

## Доступ и формат

Используется обычная сессия пользователя проекта (`sessionid`). Управлять опросами
могут активные сотрудники с `is_staff=True`. Сотрудники имеют доступ ко всем опросам.
Ученик получает доступ только к собственным назначениям.

Для всех изменяющих запросов нужны `Content-Type: application/json`, cookie сессии,
cookie `csrftoken` и заголовок `X-CSRFToken`. Токен можно получить через
`GET /staff/surveys_builder/api/metadata/`, для ученика — через `GET /surveys/api/`.
Оба запроса устанавливают CSRF cookie и возвращают `csrf_token`.
Ответы API имеют `Cache-Control: no-store`.

Даты и время передаются в ISO 8601, например `2026-11-30T23:59:00+03:00`.
`deadline: null` снимает ограничение срока. Для поля ответа типа `date` используется `YYYY-MM-DD`.
Неизвестные поля и неверные JSON-типы отклоняются.

Списки поддерживают `?page=1&page_size=50` (размер от 1 до 100):

```json
{"count": 120, "page": 1, "page_size": 50, "pages": 3, "results": []}
```

Пустой список имеет одну пустую страницу. Несуществующая страница возвращает 404.

Ошибки обработчиков API возвращаются в формате:

```json
{
  "error": {
    "code": "validation_error",
    "messages": ["Проверьте поля запроса."],
    "fields": {"title": [{"message": "Обязательное поле.", "code": "required"}]}
  }
}
```

Коды HTTP: 400 — неверные данные/недопустимое состояние, 401 — нет сессии,
403 — нет прав, 404 — объект недоступен или не найден, 405 — неверный метод,
409 — конфликт `revision` (также запрос предпросмотра уже опубликованного опроса),
415 — неверный Content-Type.
CSRF и инфраструктурные ошибки до входа в обработчик используют стандартные страницы ошибок проекта.

## Маршруты сотрудников

Базовый путь: `/staff/surveys_builder/api/`. В таблице `{id}` — ID опроса,
`{qid}` — ID вопроса, `{rid}` — ID отправленного ответа.

| Метод | Путь | Назначение |
| --- | --- | --- |
| GET | `metadata/` | Типы вопросов, статусы, значения фильтров, лимиты, CSRF |
| GET | `lookups/subjects/`, `lookups/schools/`, `lookups/courses/` | Справочники с поиском `q` и пагинацией |
| GET | `recipients/` | Поиск учеников по фильтрам аудитории |
| POST | `audience/preview/` | Подсчёт и список получателей без сохранения |
| GET, POST | пустой путь | Список / создание опроса; список фильтруется по `status` и названию `q` |
| GET, PATCH, DELETE | `{id}/` | Структура / редактирование / удаление черновика |
| GET, PUT | `{id}/audience/` | Настройка и список получателей / полная замена настройки |
| GET, POST | `{id}/blocks/` | Список / создание блока вопросов |
| GET, PATCH, DELETE | `{id}/blocks/{bid}/` | Блок / редактирование / удаление с сохранением вопросов |
| PUT | `{id}/blocks/reorder/` | Порядок всех блоков |
| POST | `{id}/questions/` | Добавление вопроса |
| PATCH, DELETE | `{id}/questions/{qid}/` | Редактирование / удаление вопроса |
| POST | `{id}/questions/{qid}/duplicate/` | Копия вопроса сразу после оригинала |
| PUT | `{id}/questions/reorder/` | Новый порядок всех вопросов |
| GET | `{id}/preview/` | Проверка готовности, получатели и токен публикации |
| POST | `{id}/publish/` | Публикация и создание назначений |
| POST | `{id}/copy/` | Копирование опроса в черновик; тело `{}` |
| POST | `{id}/close/` | Закрытие приёма ответов |
| POST | `{id}/archive/` | Архивирование опубликованного или закрытого опроса |
| GET | `{id}/results/` | Счётчики и статусы всех получателей с пагинацией |
| GET | `{id}/responses/{rid}/` | Только окончательно отправленный ответ, значения и подписи вариантов |
| GET | `{id}/results/export/` | CSV отправленных ответов, разделитель `;`, UTF-8 BOM |

Создание и копирование возвращают 201, удаление опроса — 204,
остальные успешные операции — 200. Изменять опрос и его получателей можно только в черновике.
Копия сохраняет вопросы и настройку аудитории, но не срок, ответы или назначения.
Закрытый или архивный опрос нельзя открыть повторно: для нового запуска создайте копию.
Через API удаляется только черновик без ответов. В сотруднической веб-форме
можно удалить опрос любого статуса, если на него нет ни ответов, ни черновиков;
при удалении исчезают его назначения. Если хотя бы один ученик сохранил ответ,
удаление отклоняется, а опрос можно закрыть или архивировать.

## Сценарий создания

1. `POST /staff/surveys_builder/api/`:

```json
{"title": "Обратная связь об учёбе", "description": "Расскажите, как идут занятия", "deadline": null}
```

Ответ содержит `id`, `revision`, `status: "draft"`, остальные настройки и `questions`.
Для `PATCH {id}/` достаточно изменяемых полей и актуального `revision`.

2. Настройте получателей. Сначала можно выполнить `POST audience/preview/`
с теми же полями, но без `revision`. Это ничего не сохраняет.
Затем `PUT {id}/audience/`:

```json
{
  "revision": 1,
  "mode": "filters",
  "grades": ["10", "11"],
  "profiles": ["it"],
  "statuses": ["SCHOLAR"],
  "account_active": "yes",
  "included_users": [42],
  "excluded_users": [57]
}
```

Для конкретных учеников:

```json
{"revision": 1, "mode": "individual", "included_users": [42, 43], "excluded_users": []}
```

Это полная замена настройки аудитории. Пустые фильтры не ограничивают выборку.
По умолчанию `mode=filters`, `account_active=yes`: пустая настройка выбирает всех активных учеников.
В режиме фильтров группы объединяются через И, значения одной группы — через ИЛИ.
`included_users` добавляет учеников поверх фильтров, `excluded_users` всегда имеет приоритет.
В режиме `individual` получатели определяются списками включения и исключения.
Сотрудники и суперпользователи не входят в аудиторию. Пустую аудиторию сохранить нельзя.

Дополнительные поля:

| Поле | Значение |
| --- | --- |
| `subjects`, `planned_exams`, `schools`, `courses` | Массивы ID из справочников |
| `grades`, `profiles`, `statuses`, `steps`, `form_statuses` | Массивы значений из `metadata/` |
| `account_active`, `registration_complete` | `yes`, `no` или пустая строка (любое значение) |
| `region` | Точное название региона, без учёта регистра |
| `q` | Поиск по ФИО, логину и email аккаунта/анкеты; все введённые слова должны найтись |

Школа, предмет и курс проверяются у одного выбранного курса ученика.
Класс берётся из поля проекта для 2026–2027 учебного года.
Для поиска через GET массивы задаются повторением параметров: `?grades=10&grades=11&q=Анна`.
Ответ настройки содержит `revision`, `selection` и пагинированный `recipients`.

3. `POST {id}/questions/` с новой версией из предыдущего ответа:

```json
{
  "revision": 2,
  "title": "Нужна ли помощь?",
  "description": "Выберите один вариант",
  "answer_type": "single_choice",
  "required": true,
  "options": ["Нет, всё понятно", "Да, нужна помощь"]
}
```

Ответ: `{"revision": 3, "question": {...}}`. Каждый вариант получает собственный ID.
Доступны `short_text`, `long_text`, `single_choice`, `multiple_choice`, `number`, `date`, `scale`.
До 100 вопросов; для выбора — 2–50 разных непустых вариантов до 200 символов каждый.
Можно передать `block_id` — ID блока этого опроса; `null` означает «Без блока».
При PATCH отсутствие `block_id` сохраняет текущий блок, а новый ID переносит вопрос
в конец выбранного блока. Вопросы без блока идут перед остальными.
Добавление вопросов доступно после сохранения получателей.
`PATCH` вопроса сохраняет пропущенные поля. `options` — полный массив текстов;
ID вариантов с тем же текстом сохраняются. Смена типа на текстовый убирает варианты.
Текстовые типы игнорируют переданные варианты.

Порядок вопросов задаётся целиком:

```json
{"revision": 3, "question_ids": [12, 10, 11]}
```

Чужие, пропущенные или повторяющиеся ID отклоняются без частичных изменений.
Вопросы разных блоков нельзя перемешать этим запросом: порядок внутри блоков меняется
через `questions/reorder/`, а порядок самих блоков — через `blocks/reorder/`.
Удаление вопроса, копирование вопроса, закрытие, архивирование и удаление опроса
принимают `{"revision": 3}`. Для каждого запроса используйте текущую версию.
После конфликта 409 прочитайте актуальную структуру и повторите своё изменение.

4. `GET {id}/preview/` возвращает структуру, `errors`, `recipients` и `publish_token`.
Если опрос не готов, токен равен `null`. Сам предпросмотр не создаёт назначений или ответов.
Публикация: `POST {id}/publish/` с телом:

```json
{"token": "токен из publish_token"}
```

Токен действует один час и связан с сотрудником, опросом, версией и составом получателей.
Если настройка или состав изменились, нужен новый предпросмотр.
Повтор успешного запроса не создаёт повторных назначений.

При публикации создаются `SurveyAssignment`: опрос появляется в кабинете и API выбранных учеников.
Список получателей и снимок ФИО/логина/класса/профиля/статуса фиксируются.
Изменение анкеты после публикации не изменяет назначения.
Явно выбранный неактивный ученик сможет ответить после активации аккаунта.
Каждому получателю создаётся оповещение `UserNotification` в той же транзакции.
Повторная публикация не дублирует назначения и оповещения.

## Блоки вопросов

После применения миграции `0005_question_blocks` структура опроса в API сотрудников и учеников
содержит массив `blocks`, а каждый вопрос — поле `block_id`. Плоский массив `questions`
сохраняется в порядке прохождения. Контракт отправки ответов по ID вопросов не меняется.
Существующие вопросы остаются без блока, с прежними ID и ответами.

Создание: `POST {id}/blocks/`:

```json
{"revision": 3, "title": "Об учёбе", "description": "Вопросы о занятиях и нагрузке"}
```

Ответ 201:

```json
{"revision": 4, "block": {"id": 7, "title": "Об учёбе", "description": "Вопросы о занятиях и нагрузке", "position": 1}}
```

До 50 блоков на опрос, название — до 200 символов, описание — до 3000.
Название обязательно. Блоки можно менять только в черновике; все изменения требуют
актуальной версии **опроса**. Пустые блоки можно сохранять, но перед публикацией их
нужно заполнить вопросами или удалить.

`PATCH {id}/blocks/{bid}/` принимает `revision` и изменяемые `title` / `description`.
`DELETE` принимает `revision`, удаляет только блок и переносит его вопросы в конец
раздела «Без блока». Варианты ответа и ID вопросов сохраняются.

Перестановка блоков: `PUT {id}/blocks/reorder/`:

```json
{"revision": 4, "block_ids": [9, 7, 8]}
```

Нужно передать все блоки этого опроса ровно по одному разу. Вместе с блоками
переставляются их вопросы. При копировании опроса создаются новые блоки и новые
связи вопросов с ними. CSV подписывает колонки вопросов из блоков как `[Название блока] Вопрос`.

## API ученика

Базовый путь: `/surveys/api/`. Здесь `{id}` — **ID назначения**, не ID опроса.
В веб-интерфейсе `/surveys/{id}/` каждый блок показан на отдельной странице
через параметр `?page=N`; переход дальше сохраняет только текущий блок.
API сохраняет прежний контракт полного ответа и не использует этот параметр.

| Метод | Путь | Назначение |
| --- | --- | --- |
| GET | пустой путь | Только свои опросы, пагинация и CSRF-токен |
| GET | `{id}/` | Структура опроса и собственный ответ |
| PUT | `{id}/response/` | Полностью сохранить черновик или окончательный ответ |

Настройка аудитории и чужие данные ученику не выдаются.
В деталях назначения `response` содержит `revision` и `answers`.
До первого сохранения `revision=0`. Пример сохранения:

```json
{
  "revision": 0,
  "final": false,
  "answers": {"10": "Текст ответа", "11": 25, "12": [31, 32]}
}
```

Ключи `answers` — строковые ID вопросов этого опроса.
При `PUT` передавайте весь ответ: пропущенные вопросы очищаются.
Для окончательной отправки передайте `final: true` с текущей версией ответа.
При сохранении черновика обязательные вопросы можно пропускать; при отправке они проверяются.
После отправки ответ изменить нельзя. После срока, закрытия или архивирования приём заблокирован.
Повторный `PUT` уже отправленного ответа возвращает 400 без изменения данных.
Для черновика устаревший `revision` возвращает 409; перед повтором нужно получить
текущую версию через `GET {id}/`.

| Тип вопроса | JSON-значение |
| --- | --- |
| `short_text`, `long_text` | Строка до 1000 / 10000 символов |
| `single_choice` | ID варианта своего вопроса |
| `multiple_choice` | Массив ID вариантов своего вопроса; дубли удаляются |
| `number` | Число или десятичная строка, до 18 цифр, до 6 после точки; ответ хранится строкой |
| `date` | Строка `YYYY-MM-DD` |
| `scale` | Целое от 1 до 5 |

Для пустого ответа можно передать `null`. Обязательность проверяется при окончательной отправке.
Версия ответа независима от версии опроса.

## Результаты и проверки

Сотруднику доступны количества `total`, `submitted`, `started`, `not_started`.
Черновики ученика учитываются в `started`, но их текст и ID ответа сотрудникам не выдаются.
Детализация и CSV содержат только окончательно отправленные ответы.
CSV подставляет подписи вариантов и защищает значения от выполнения формул в Excel.

```sh
python manage.py test surveys_builder --settings=Putevka.survey_test_settings
python manage.py check --settings=Putevka.survey_test_settings
python manage.py makemigrations --check --dry-run --settings=Putevka.survey_test_settings
```

Тесты используют SQLite в памяти. Проверка конкурентных блокировок PostgreSQL
в этот набор не входит.
