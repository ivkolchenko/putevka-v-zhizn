# JSON API конструктора

Сессия Django, активный сотрудник `is_staff=True`. Все изменяющие запросы защищены CSRF.
Основной формат — `application/json`. Для загрузки изображений используется POST multipart.
Базовый путь сотрудника: `/staff/surveys_builder/api/`, ученика: `/surveys/api/`.

Получить CSRF-токен и cookie: `GET metadata/` сотрудника либо `GET /surveys/api/` ученика.
Передавать cookie сессии, `csrftoken` и заголовок `X-CSRFToken`.
Ответы содержат `Cache-Control: no-store`.

## Общие правила

Списки имеют `count`, `page`, `page_size`, `pages`, `results`.
Параметры `?page=1&page_size=50`, размер страницы 1–100.
Пустой список имеет одну страницу, несуществующая страница — 404.

Все изменения существующих записей требуют целого `revision` **опроса**,
в том числе изменения блоков, вопросов, секций и вставка из библиотеки.
Версия ответа ученика независима и начинается с 0 до первого сохранения.

Ошибки:

```json
{"error":{"code":"validation_error","messages":["Проверьте поля запроса."],"fields":{}}}
```

400 — неверные данные/состояние, 401 — нет сессии, 403 — нет прав, 404 — нет объекта,
405 — неверный метод, 409 — конфликт версии, 415 — неверный Content-Type.
CSRF и инфраструктурные ошибки до входа в обработчик используют страницы ошибок проекта.

## Сценарий

1. Создать опрос: `POST /staff/surveys_builder/api/` с `title`, `description`.
2. Создать блоки, затем содержимое в каждом блоке.
3. Сохранить назначение и необязательный дедлайн: `PUT {id}/audience/`.
4. Получить `publish_token` через `GET {id}/preview/` и отправить его в `POST {id}/publish/`.

Создание/изменение названия опроса больше не принимает `deadline`: он задаётся на этапе назначения.
Вопрос обязательно связан с блоком этого опроса. Создание вопросов не требует сохранённой аудитории.

## Опросы и назначения

| Метод | Путь | Назначение |
| --- | --- | --- |
| GET | `metadata/` | Типы вопросов, значения фильтров, лимиты и требования к получателям |
| GET | `lookups/subjects/`, `lookups/schools/`, `lookups/courses/` | Справочники с поиском q и пагинацией |
| GET | `recipients/` | Допустимые получатели, фильтры в query string |
| POST | `audience/preview/` | Проверить подбор получателей без сохранения |
| GET, POST | пустой путь | Список обычных опросов / создание |
| GET, PATCH, DELETE | `{id}/` | Структура / название и описание / удаление черновика |
| GET, PUT | `{id}/audience/` | Получатели / полная замена назначения и дедлайна |
| GET | `{id}/preview/` | Проверка готовности, получатели, токен публикации |
| POST | `{id}/publish/` | Публикация с `token` |
| POST | `{id}/copy/` | Копия в черновик, тело `{}`; аудиторию нужно перепроверить |
| POST | `{id}/close/`, `{id}/archive/` | Смена состояния, тело с revision |
| GET | `{id}/results/` | Счётчики и статусы получателей |
| GET | `{id}/responses/{rid}/` | Только отправленный ответ |
| GET | `{id}/results/export/` | CSV, UTF-8 BOM, разделитель `;` |

Новые назначения всегда ограничены активными учениками с завершённой регистрацией.
Сотрудники, суперпользователи, неактивные и не завершившие регистрацию исключены даже
при ручном назначении. Доступны только режимы `filters` и `individual`.

По фильтрам:

```json
{"revision":5,"mode":"filters","grades":["10","11"],"profiles":["it"],"deadline":null}
```

Конкретным участникам:

```json
{"revision":5,"mode":"individual","included_users":[42,43],"deadline":null}
```

В режиме filters нельзя передавать непустой included_users. В individual фильтры игнорируются.
Исключения и дополнения к фильтрам больше не поддерживаются.

Допустимые фильтры: `grades` (только 10/11), `profiles`, `statuses` (статус участия),
`steps`, `subjects`, `planned_exams`, `schools`, `courses`.
Между группами — И, внутри группы — ИЛИ. Школа, предмет и курс относятся к одному выбранному курсу.
Массивы для GET передаются повторением параметров: `?grades=10&grades=11`.

Удалены: `form_statuses`, `account_active`, `registration_complete`, `region`, `q`, `excluded_users`.
Через API неизвестные поля отклоняются.
Опциональное `active_filters` — массив имён добавленных фильтров для восстановления интерфейса.
Он не ограничивает выборку сам по себе: условия определяются выбранными значениями.

`deadline: null` или пустая строка означает отсутствие ограничения. Дата задаётся в ISO 8601
с часовым поясом, например `2026-11-30T23:59:00+03:00`, и должна быть в будущем.
При PUT отсутствие deadline также снимает ограничение.

## Блоки, вопросы и секции

| Метод | Путь | Назначение |
| --- | --- | --- |
| GET, POST | `{id}/blocks/` | Блоки / создание |
| GET, PATCH, DELETE | `{id}/blocks/{bid}/` | Метаданные / изменение / удаление блока вместе с содержимым |
| PUT | `{id}/blocks/reorder/` | `revision`, `block_ids`: все блоки по одному разу |
| POST | `{id}/questions/` | Добавить вопрос с обязательным block_id |
| PATCH, DELETE | `{id}/questions/{qid}/` | Изменить / удалить вопрос |
| POST | `{id}/questions/{qid}/duplicate/` | Дублировать вопрос, revision |
| PUT | `{id}/questions/reorder/` | revision и все question_ids, перестановка внутри блоков |
| POST | `{id}/blocks/{bid}/sections/` | Текстовая секция, JSON или multipart |
| GET, PATCH, POST, DELETE | `{id}/blocks/{bid}/sections/{sid}/` | Просмотр / JSON / multipart / удаление |
| POST | `{id}/blocks/{bid}/sections/{sid}/up/`, `down/` | Переставить секцию среди вопросов и текста |

Пример создания блока:

```json
{"revision":1,"title":"Учёба","description":"О занятиях","visibility_filters":{"profiles":["it"]}}
```

Фильтры видимости совпадают с фильтрами назначения: grades (10/11), profiles, statuses,
subjects, planned_exams, schools, courses, steps.
Пустой объект означает видимость всем назначенным участникам. Они не добавляют получателей.
При PATCH отсутствие visibility_filters сохраняет настройки; `{}` снимает ограничения.
Видимость фиксируется для каждого назначения при публикации. Скрытые блоки и их содержимое
не возвращаются ученику, скрытые обязательные вопросы не требуют ответа.
Если кому-то из выбранных получателей не виден ни один блок, публикация блокируется.

Вопрос:

```json
{"revision":2,"block_id":7,"title":"Какой формат удобнее?","answer_type":"single_choice","required":true,"options":["Онлайн","Очно"]}
```

Типы: short_text, long_text, single_choice, multiple_choice, number, date, scale.
При PATCH вопроса отсутствие block_id сохраняет блок, другой ID переносит вопрос в конец нового блока.
`null` не допускается. Существующие варианты с тем же текстом сохраняют ID.

Текстовая секция:

```json
{"revision":3,"title":"Инструкция","text":"Прочитайте перед ответом","image_alt":""}
```

Для картинки — POST multipart с теми же текстовыми полями, `revision` и файлом `image`.
Для редактирования картинки POST выполняется по адресу существующей секции.
JSON PATCH сохраняет картинку; `remove_image: true` снимает её. Пустая секция без текста
и картинки не допускается. Текст экранируется, HTML не исполняется.

image_url ведёт на защищённый маршрут: нужна сессия сотрудника либо назначение с доступом к блоку.
Картинки не выдаются из публичного MEDIA_URL.

Блок может содержать только текстовые секции и картинки, без вопросов. Такой опрос можно
отправить как подтверждение ознакомления. Полностью пустой блок не публикуется.

Структура опроса содержит `blocks`, плоский `questions`; у вопроса есть block_id и block_position.
У блока `items` — упорядоченные элементы с type (`question` / `section`) и id;
для секции также передаются title, text, image_url, image_alt, position в объекте section.
Видимые ученику блоки выдаются без внутренних фильтров видимости.

Лимиты: 50 блоков, 100 вопросов на опрос, 100 секций на блок, 2–50 вариантов до 200 символов.
Картинки до 5 МБ и 6000×6000, PNG/JPEG/GIF/WebP; секция до 20 000 символов.

## Библиотека черновиков блоков

| Метод | Путь | Назначение |
| --- | --- | --- |
| GET, POST | `block-templates/` | Библиотека / новый черновик по title, description, visibility_filters |
| POST | `{id}/blocks/{bid}/save-template/` | Сохранить независимую копию блока в библиотеку, revision |
| POST | `{id}/blocks/import/` | Вставить копию: revision целевого опроса и template_id |

Новый черновик — отдельная запись опроса `is_block_template=true` с единственным блоком.
Редактируется теми же маршрутами блоков/вопросов/секций. Не появляется в обычном списке,
не может назначаться или публиковаться самостоятельно. Удаление — DELETE `{id}/`.
Вставка копирует содержание, варианты и фильтры; последующие изменения исходника не меняют копию.
Файлы картинок сохраняются, пока на них могут ссылаться скопированные блоки.

## Ученик

Здесь `{id}` — **ID назначения**.

| Метод | Путь | Назначение |
| --- | --- | --- |
| GET | `/surveys/api/` | Только свои назначения, пагинация и csrf_token |
| GET | `/surveys/api/{id}/` | Только видимые блоки, вопросы, секции и собственный ответ |
| PUT | `/surveys/api/{id}/response/` | Полностью заменить черновик / отправить ответ |

```json
{"revision":0,"final":false,"answers":{"10":"Текст","11":25,"12":[31,32]}}
```

Пропущенные вопросы очищаются. `final: true` проверяет обязательность **видимых** вопросов.
Подмена скрытого или чужого ID отклоняется. После отправки ответ изменить нельзя.
Числа сохраняются десятичными строками (18 цифр, до 6 после точки), даты — YYYY-MM-DD,
варианты — ID своих вариантов, шкала — 1–5. Для пустого ответа допустим null.
Текст short_text — до 1000 символов, long_text — до 10000.

## Миграция и проверки

Применить `python manage.py migrate`. Миграция 0006 сохраняет старые вопросы и ответы,
создаёт блок для ранее несгруппированных вопросов, фиксирует видимость исторических назначений.
Черновики требуют повторного выбора аудитории по новым правилам.

```sh
python manage.py test surveys_builder --settings=Putevka.survey_test_settings
python manage.py check --settings=Putevka.survey_test_settings
python manage.py makemigrations --check --dry-run --settings=Putevka.survey_test_settings
```

SQLite-тесты не проверяют конкурентные блокировки PostgreSQL.
